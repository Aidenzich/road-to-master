# 第一章:問題設定與單卡的極限

> [回導讀](../README.zh-TW.md) | [證據與來源](08-evidence.md)

> 這章回答:**一次訓練或推論,一張 GPU 的記憶體到底裝了什麼?為什麼常常放不下,或放得下也不夠快?** 這是整份研究的地基——要判斷「該不該用多卡」,得先看清楚「一張卡的極限在哪」。後面每一章談的多卡做法,都是為了突破這章描述的兩道牆(記憶體牆與速度牆)。

## 我們手上有什麼、想做什麼

先把場景講清楚。手上有四張 GPU:一張 RTX 5090(32 GB 顯示記憶體)和三張 L40S(每張約 46 GB 可用)。關鍵限制有兩個:

1. **依需求設定,四張卡分屬四台不同主機**,透過**一般乙太網路**互通;實際網卡線速與生效路徑尚未量測。這兩種 GPU 也都不支援 **NVLink**——下面先解釋這是什麼,以及為什麼不能直接加裝。
2. 因此本平台上「一張卡送資料給另一張卡」永遠等於「一台主機透過網路送給另一台主機」——這句話會在後面每一章反覆出現,是理解一切取捨的樞紐。

想做的事:用這些卡訓練或服務大型語言模型(LLM,large language model,如 Llama、Qwen、Mixtral 這類數十億到數百億參數的模型)。問題是:哪些模型放得下一張卡?放不下的要怎麼分到多張卡?分了之後值不值得?

要回答,先分清楚「GPU 本身能算、能裝多少」和「GPU 之間能多快交換資料」。後者需要先認識 NVLink,再回頭算單卡的記憶體帳。

## 先認識 NVLink:GPU 之間的專用資料通道

想像兩張 GPU 各算完模型的一部分,接著要交換結果。除了「算得快」,它們還需要「送得快」。**NVLink 是 NVIDIA 的高速硬體互連技術**,此處討論的是 GPU 與 GPU 之間的資料交換;它不是訓練框架,也不是安裝後就能讓網路變快的軟體。[W42]

先把三種容易混在一起的連線分開:

| 名稱 | 在這份研究中的角色 | 不能把它誤認成什麼 |
| --- | --- | --- |
| PCIe | 主機內連接 GPU、網卡等裝置的匯流排 | 不是四台獨立主機之間的乙太網路連線 |
| 乙太網路(Ethernet) | 本題四台主機之間傳資料的網路 | 線速、延遲與實際可用頻寬仍要量測 |
| NVLink | 支援它的 GPU／系統所提供的專用高速互連 | 不是所有 NVIDIA GPU 都有,也不是通用外接網卡 |

**NVLink 橋接器**用於相容卡型與硬體配置的連接;**NVSwitch／NVLink Switch**則是把多條 NVLink 接起來的交換硬體。兩者都不能替不支援 NVLink 的 GPU 憑空增加能力。也不要反過來記成「NVLink 永遠只能在單一主機內」:專門設計的 NVLink Switch 系統可跨節點、擴展到機架,但那是不同的整套硬體平台,不是替本題四台普通主機接一條線。[W42]

### 為什麼這四張卡不能直接加裝?

最初的「無 NVLink」來自任務明列的環境限制,不是研究者自行排除升級。補查 NVIDIA 官方規格後,還可以確認更具體的硬體原因(查閱日:2026-09-08):

- **RTX 5090:** 官方規格的 `NVIDIA NVLink™ (SLI-Ready)` 是 **No**。[W40]
- **L40S:** 官方規格的 `NVIDIA® NVLink® Support` 也是 **No**。[W41]

所以此處「不能加裝」的精確意思是:**保留現有 RTX 5090 與 L40S,不能靠購買 NVLink 橋接器、更新驅動,或調整 K3s／Volcano／HAMi 設定取得 NVLink。** 把這些卡搬到同一台主機也不會改變型號本身的支援能力。若真的要採用 NVLink,需另選支援的 GPU 型號與相容主機／互連配置;這屬於更換硬體平台,不是現有卡的小升級。[W40][W41][W42]

### 沒有 NVLink,不等於不能做多卡

差別是**通訊走哪裡、成本多高**,不是「多卡功能被關掉」。後文的資料並行、張量並行與管線並行仍可透過受支援的其他通訊路徑運作;在本題跨主機配置下需要經過網路。是否划算,必須比較模型的計算時間、交換資料量、同步次數與實測網路表現,不能只看「無 NVLink」就宣布某種策略必敗。

同樣地,有 NVLink 也不代表資料交換免費,更不代表幾張卡的記憶體會自動變成一張不需切分模型的大卡。它改善的是互連條件;模型如何分配與同步,仍是第三章要解決的問題。現在先回到起點:為什麼一張卡可能放不下模型?

## 一次訓練,GPU 記憶體裝了四樣東西

想像模型是一個有幾十億個「旋鈕」的巨大函數,每個旋鈕就是一個**參數**(parameter,也叫權重)。訓練就是反覆地:讀一批資料 → 算出預測(**前向傳遞**,forward pass)→ 比對答案算出誤差 → 反推每個旋鈕該往哪轉(**反向傳遞**,backward pass)→ 微調旋鈕(**優化器更新**,optimizer step)。這個迴圈裡,GPU 記憶體同時裝著四類東西:

- **參數**:那幾十億個旋鈕本身的數值。
- **梯度**(gradient):反向傳遞算出的「每個旋鈕該往哪個方向、轉多少」,和參數一樣多。
- **優化器狀態**(optimizer state):現代訓練幾乎都用 Adam 這類優化器,它為了讓調整更穩,會為**每個**參數額外記住幾個輔助數字(動量與變異數)。這是記憶體的隱形大戶。
- **activation**:前向傳遞途中產生的中間結果(每一層的輸出),反向傳遞時要用它們回推梯度,所以得暫存。它的大小隨批次大小(batch size)與序列長度成長,不隨參數量固定。

一個常見的直覺陷阱是「模型 8B(80 億參數),那大概要 8B×幾 byte 就夠了吧」。實際遠不止,因為梯度和優化器狀態會把它翻好幾倍。要算清楚,得先引入「精度」這個變數。

### 精度:同一個數字,可以用 2、4 或 1 個 byte 存

一個參數要佔多少記憶體,取決於用什麼**數值精度**(dtype)存:

- **fp32**(32 位元浮點):4 個 byte,範圍與精度都足,但最佔空間。
- **fp16 / bf16**(16 位元):各 2 個 byte。bf16(brain float 16)指數位寬和 fp32 一樣,動態範圍大;fp16 尾數較多但範圍小,容易「下溢」(underflow,小數字被歸零),所以用 fp16 訓練通常要搭配 loss/gradient scaling 放大再縮回以防歸零,bf16 通常免此步[W13]。
- **fp8**(8 位元):1 個 byte,又分 E4M3(存權重、activation)與 E5M2(存梯度),範圍精度更窄,需要逐張量的縮放校正[W14]。

現代訓練普遍用**混合精度**(mixed precision):矩陣乘法之類用 16 位元算得快,但誤差累加(reductions)常需要 fp32 的動態範圍才不失真[W13]。這帶出一個關鍵區分,後面幾章都會用到:**「用什麼精度算」和「透過網路傳什麼精度」是兩回事**——可以用 bf16 甚至 fp8 傳梯度來減少網路流量,即使計算時另有一份 fp32。

### 記憶體帳本:混合精度 Adam 是「16 倍參數量」

把上面四類東西按精度加起來,就能得到一個可核算的帳本。以參數量 Ψ(讀作 psi,就是「模型有幾個參數」)、混合精度 Adam 為例,ZeRO 論文逐項給出(單位 byte)[W10]:

- fp16 參數:2Ψ
- fp16 梯度:2Ψ
- 優化器狀態(fp32 主權重 4Ψ + 動量 4Ψ + 變異數 4Ψ):共 12Ψ

$$
\text{每張卡狀態記憶體} = \underbrace{2\Psi}_{\text{參數}} + \underbrace{2\Psi}_{\text{梯度}} + \underbrace{12\Psi}_{\text{優化器狀態}} = 16\Psi
$$

論文原文即「In total, this results in 2Ψ+2Ψ+KΨ=16Ψ bytes of memory requirement」,其中混合精度 Adam 的 K=12[W10]。注意這 16Ψ**還沒算 activation**——activation 另計,且吃批次與序列長度。

### 走一遍 Llama-3-8B 的數字(worked example)

把帳本套到一個真實模型。Llama-3-8B(官方標 8B,取 Ψ ≈ 8.0×10⁹[W16]):

$$
16\Psi = 16 \times 8.0\times10^{9}\ \text{byte} = 128\times10^{9}\ \text{byte} \approx 128\ \text{GB}
$$

也就是說,**光是把 8B 模型的參數、梯度、優化器狀態放進去,單張卡就要 128 GB**——這還沒算 activation。對照本平台最大的一張卡是 L40S 的 46 GB,差了將近三倍。

同一個模型,如果只是**推論**(inference,只做前向、不訓練),帳本小得多:不需要梯度和優化器狀態,主要就是參數(8B 用 bf16 ≈ 16 GB)加上服務時的 **KV cache**(推論時暫存已算過 token 的鍵值,隨並發與序列長度成長)。所以 8B **推論**放得下單張 L40S,**全參數訓練**卻遠遠放不下——同一個模型,兩道題目的記憶體天差地遠。這個「推論可行、訓練不可行」的落差,是本研究反覆出現的分水嶺。

## 兩道牆:為什麼單卡常常不夠

有了帳本,「單卡不夠」可以精確拆成兩種情況:

1. **記憶體牆(放不下)。** 如上,8B 全參數訓練要 128 GB,單卡裝不下。任何超過單卡容量的模型或訓練配置,都必須把某樣東西(參數、梯度、優化器狀態,或 activation)切開分到多張卡——而一旦切開,卡與卡之間就得**交換資料**。交換什麼、多少、多頻繁,正是第二章的主題。
2. **速度牆(放得下但不夠快)。** 即使放得下,一張卡的算力有上限;想更快,直覺是「多找幾張卡一起算同一批資料」。但多卡一起算,每一步結束時必須把各卡算出的梯度合起來對齊,否則四張卡會各自往不同方向調旋鈕。這個「對齊」也是一次跨卡交換。

兩道牆的共同出口都是「多卡」,而多卡的共同代價都是「跨卡交換資料」。NVLink 這類高速互連能降低此成本,但不會消除它;本平台跨卡等於跨一般網路,代價可能大到讓多卡不划算。要判斷划不划算,必須先弄懂「要交換什麼、一次交換要多久」。

**這就是為什麼下一章要先講通訊,而不是急著講各種切模型的花招:** 所有並行策略的成敗,最終都由「它逼出多少跨卡通訊、以及本平台跑這些通訊有多慢」決定。第二章先建立通訊的字彙(rank、集體通訊)與成本模型,第三章才用它來評斷每一種切法。
