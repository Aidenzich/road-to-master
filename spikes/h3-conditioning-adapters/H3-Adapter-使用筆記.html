01

先看它改哪裡

Adapter 是適配方式的總稱。三者都可能使用 .safetensors，但檔案裡存的東西不同，不能互換 loader。普通 LoRA 是權重增量，語義橋是小型條件轉換網路，RefMod 是可重用的參考 latent。

02

VAE 與 RefMod：在哪一層匯合？

對視覺素材而言，VAE 是像素與 latent 之間的轉換器：參考圖片／影片經 encoder 變成 latent，生成結果經 decoder 還原為影格。但 H3 還有文字條件與噪聲輸入，並非所有入口都經過 VAE。下面聚焦視覺參考與影片生成；音訊另有自己的編碼／解碼路徑。

RefMod 注入的是參考條件，不是替換待生成的 latent。

ComfyUI 先把參考區塊加到 conditioning 的 refs / minimax_refs；模型每次 forward 再把參考與目標影片整理成 tokens，送入同一 packed sequence 的 DiT attention。

展開逐階段中文說明

這份 latent 保存了什麼？

是來源素材的視覺表示，可能包含人物、衣服、姿勢與背景；不是已分離的「純角色身份向量」。使用先前成片時，是重新編碼成片，不是回收那次生成的中間狀態。

VAE 是否每一步都執行？

一般情況先編碼參考，採樣在 latent／token 空間反覆運算，完成後才解碼目標影片。RefMod 可重用已保存的參考 latent；實驗性 Text Encode 路徑仍可能解碼參考供 Qwen 使用。

03

LoRA：調整模型的運算

普通 LoRA 用低秩矩陣表示權重變更。模型推論時套用這份增量，改變生成傾向；動作 LoRA 與少步數加速 LoRA 屬於不同用途。

  1. 1.

    接 MODEL

    原底模輸出接到 LoraLoaderModelOnly。

  2. 2.

    選檔與強度

    設定 lora_name 與 strength_model，多檔依固定順序串接。

  3. 3.

    送入採樣

    輸出 MODEL 經既有 patches 後，供 Guider 與 Scheduler 使用。

目前 013 的 LoRA強度用途
Turbo 8-step1.0少步數蒸餾
Combat V20.6武打動作與受擊
Camera Motion v10.8運鏡傾向
Spatial Physics clean30000.3動作與物理互動傾向

013 實際跑 20 steps，使用者評價「效果不錯」。這是特定配置的回饋；8-step 命名不會把採樣鎖在 8 步，也不代表增加步數必定更好。

strength 與 steps 是不同控制。

0.6 是權重增量的縮放，不是「模型 60%」。一般加速 LoRA 主要減少所需採樣次數，不自動讓相同 steps 的每一步更快。DMAD／PDD 等特殊配方另外核對採樣器、sigma 與輸出頭。

04

語義橋：轉換模型收到的條件

Semantic Bridge v1 是 conditioning-space adapter。它將 H3 原有的條件表示送入小型 MLP，再與原條件混合。SenseNova U1.5 只作為研究與蒸餾的老師，推論時不需要載入它。來源 [1–2]

這裡處理的 H 是文字編碼後的條件表示，不是 VAE 編碼出的視覺 latent。語義橋保留原序列長度，改變每個位置的表示；RefMod 則提供額外的參考 tokens。圖中原 H 的旁路與 MLP 轉換路在 α 混合處匯合，之後才進入既有 H3 模型。

那份 11 MB 權重，是誰學到了什麼？

它就是作者訓練完成的 student MLP，也就是 learned adapter。兩個名稱指同一個模組：student 描述蒸餾時的角色，adapter 描述部署後轉換 conditioning 的用途。圖中的橘色方塊同時代表這個網路與它載入的權重，沒有另一個「adapter 模型」接在 MLP 前面。我們尚未訓練或部署這個工具。

元件在研究中的作用使用發布版時
SenseNova-U1.5-8B-MoT能理解文字／圖片，也能生成與編輯圖片的統一多模態模型；這項研究取它閱讀 prompt 的 hidden states。不載入
SenseNova → H3 的映射投影將 teacher 表示轉成 H3 相容的空間，與 SenseNova 合成 Full Bridge teacher 流程。不載入
約 11 MB 的發布權重student MLP 學會從 H3 conditioning 預測 teacher-derived 表示後，保存的參數。載入這一份即可

精確的 teacher 不是單指 SenseNova，而是SenseNova 加上已訓練的映射投影所產生的 target。研究利用的是內部表示，不是讓 SenseNova 生成教學圖片，也不是把它輸出的文字當成重寫後的 prompt。來源 [1、8–10]。

作者公開的訓練流程

  1. 1.

    建立跨模型映射

    相同 prompt 取 SenseNova 第 32 層與 H3 文字編碼器第 49 層 hidden states。訓練 rank-128 投影，將 SenseNova 表示映射至 H3 空間；這不是 DiT 的層數。

  2. 2.

    產生 teacher targets

    SenseNova 表示先 RMS 正規化，再經映射投影，取得 teacher-derived 表示 S。另一條路保留同 prompt 的 H3 conditioning H。

  3. 3.

    訓練 student MLP

    將正規化的 H 輸入 MLP，預測 S。用 loss 更新 MLP 權重；完成後，發布這組小型網路參數。

公開 V3 腳本可核對的設定
資料600 個 prompts：440 個開發 prompts＋160 個原先稱為 strict OOD 的 prompts。V3 分為訓練 500、驗證 100；驗證含 70 個主分布與 30 個原 OOD。
Student 網路5120 → 512 → 512 → 5120，兩個 SiLU 非線性。
更新方式AdamW、學習率 3e-4、40 epochs、每批 1024 tokens；若找到 V2 checkpoint，先用其權重初始化。
Loss0.55 × 表示 cosine loss ＋ 0.40 × 修正方向 cosine loss ＋ 0.05 × 正規化 MSE。
Loss 的細節修正方向先將預測與 target 做幅度匹配，再各自減去 H 參照。訓練迴圈實際傳入的是正規化 H；評估使用保存的原 H，兩者不能無條件當成完全相同的目標。

這是公開 V3 原始程式與報告可確認的內容，不是我們重跑訓練的結果。作者提供資料與 raw scripts，但大型 hidden-state caches 未隨附；腳本含本地路徑，需要重建環境與中間資料，不能當成已完成的本地重現。來源 [9–11]。

新 prompt 與特定目標：能做的事情不同

訓練固定的是轉換規則與權重；不同 prompt 對應不同 H，也會得到不同的預測 S。發布版可以處理新 prompt，但每次仍只執行既有的 H3 編碼器與固定 MLP，不會再詢問 SenseNova，也不會從這次影片自動學習。

想做什麼需要重新訓練嗎？
換 prompt、角色、場景，套用現成轉換不需要；使用同一份 11 MB adapter，也不必下載 SenseNova。
調整 α不需要；只改這次推論的混合強度，不會保存新能力。
讓某種特定能力學進新 adapter，保存並反覆使用現成節點沒有這種個別學習功能，需要另設計與訓練／微調 adapter。是否適合語義橋，要由目標與資料判斷。
重現作者的 SenseNova 蒸餾流程需要 SenseNova／映射或預先產生的 teacher targets，以及資料與訓練流程；有完整預算好的 targets 時，student 訓練本身可不再載入 teacher。

它學會模仿表示，並不等於證明影片更正確

最精確的定位是「模仿 teacher 表示的輕量 conditioning 轉換器，效果待驗」。作者希望影響空間關係、數量與動作限制等語義，但 student 的 loss 沒有直接評分影片是否真的出現正確左右手、數量或物理互動，也沒有把完整 SenseNova 的推理能力搬進 H3。

  • 報告的 representation cosine 0.995890 衡量對 teacher 表示的接近程度，不是 99.6% 提示詞遵從率或畫質提升。
  • V3 訓練已使用 130 個原先的 OOD prompts；其中剩下的 30 個作驗證，不能把相關指標解讀為完全陌生分布上的泛化證明。
  • MLP 的推論輸入只有 H3 conditioning。若某項資訊在 H 中無法辨識，它沒有額外查詢 teacher 或原始世界的管道；能否從保留的訊號推回有用表示，需要驗證。
  • 公開的少量影片 A/B 只支持特定案例；不能據此認定會改善我們的武打、角色保持、黑幕或物理互動。

與 TVA 的共同概念是利用已有 latent／表示幫助下游模型；融合位置不同。TVA 在序列位置上融合特徵，語義橋轉換現有 conditioning，RefMod 加入參考 tokens。這個概念相似性本身不構成生成品質的證據。來源 [1、9–12]。

  1. 1.

    原生 H3 編碼

    保留原 prompt、首幀與 I2VA 節點，取得 positive／conditioning。

  2. 2.

    Semantic Bridge

    RMS 正規化 → 5120→512→512→5120 MLP → 幅度匹配與混合。

  3. 3.

    原採樣流程

    新 conditioning 接 BasicGuider；原 latent、MODEL 與採樣設定沿用。

05

RefMod：保存並重用參考素材

你提到的 refmode，這份筆記按 H3 社群工具 RefMod 說明。它將圖片、影片或音訊的 VAE latent 存成參考檔，生成時走原生參考 token 路徑。不是訓練 H3 權重，也不會自動分離角色、服裝和背景。來源 [3–5]

RefMod 到底怎麼產生？

選 Full Reference／encode 時，核心就是把參考圖片或影片送進 H3 自己使用的 video VAE encoder，保存編碼結果。這個 video VAE 也能處理單張圖片，不必先生成一支角色影片。

  1. 1.

    前處理素材

    圖片調整尺寸；影片依節點設定取樣與對齊影格。前處理可能改變原素材保留的細節。

  2. 2.

    執行 VAE 編碼

    呼叫 vae.encode(src)，得到 H3 視覺 latent；節點檢查其形狀為 [1, 24, T, H, W]。T、H、W 是 latent 尺度。

  3. 3.

    封裝並保存

    encode 模式保存編碼後的 latent（程式轉為 FP16），再搭配素材類型、尺寸等 metadata 存成 RefMod，供下一次載入。

說「推論一次」指的是什麼？製作 Full Reference RefMod
執行已訓練模型來取得輸出算。會執行 VAE encoder 的推論／編碼作業；實際可分塊或分批，不代表只有一次底層 forward。
完整執行一次 H3 影片生成不算。不需要 DiT 去噪採樣、生成 prompt 或影片採樣 steps，也不會因此產生新影片。
訓練角色或修改 H3 權重不是。這一步保存素材的視覺表示，未把角色學進 H3 權重。
Compressed／training 會多做什麼？

同樣先用 VAE 編碼，再將 latent pooling 成較小網格；若啟用 refinement，會多次以梯度最佳化小 latent 的重建誤差。這些是 latent 最佳化步數，不是 DiT 生成 steps，也不訓練 H3 權重。只選 encode 則沒有這段壓縮最佳化。

直接接一般 VAE Encode 可取得核心 latent，但裸 latent 還不等於可由 RefMod loader 使用的完整檔案；需由對應節點封裝 metadata 並保存。Full Reference 的「完整」指保留前處理後的編碼表示，並非原像素無損，也不是純角色身份向量。來源 [3–4]。

先建立參考檔

  1. 1.

    準備素材與 VAE

    圖片／影片影格接 Create H3 RefMod，並接原生 H3 video VAE。

  2. 2.

    先保留完整資訊

    選 Full Reference（encode），檢查 details／Inspect 中的範圍、shape 與 tokens。

  3. 3.

    保存與重用

    保存到 models/refmods/，每名角色分開命名，再用 Load H3 RefMods 載入。

以上是一般環境的參考指令，尚未在叢集執行。需原生 H3 支援；影片 folder loader 的 OpenCV／imageio 是可選後端。音訊素材需另接 H3 audio VAE，可用 Master 節點整理。

載入接法：兩條路擇一

A．既有條件＋Apply

Load H3 RefMods 的 bundle 與原生 reference conditioning 接到 Apply H3 RefMod，再送 Guider。生成 latent 沿用相容工作流。

這會加參考 tokens，但不會把新增素材呈現給 Qwen，不能推定檔名就是 trigger。

B．需要編號指向素材

Load H3 RefMods＋H3 CLIP＋video VAE＋完整 prompt，接 H3 RefMod Text Encode；輸出的 conditioning 送 Guider。

屬實驗性呈現路徑。它已注入 refs，不能再 Apply 或 Bridge 同一 bundle。

參考標籤以 reference_map 為準。

不同模態分開編號、零強度排除，copies 可能增加標籤。多張照片若存成 video-kind，可能只是一個 Video 標籤。<Subject n> 不會自動綁定 loader 欄位；正式 prompt 仍遵循對應 H3 schema。

比較完整參考時可先用 strength 1、retention 1、copies 1、constant／linear／curve_value 1、override 關閉、scramble_seed −1。這是診斷起點，不是所有素材的最佳值。

06

成本與容易誤解的地方

問題已核對的界線
RefMod 小檔案＝零成本？不是。生成成本取決於保留的參考 tokens；encode 仍有 attention 成本。
RefMod 的 training＝角色訓練？不是。現有壓縮最佳化只重建 latent，沒有 DiT、身份辨識或 motion objective。
壓縮越小越好？可能丟掉臉、衣服細節與快速動作；更多重建步數也不等於學會招式。
能精確複製武打？不保證。影片動作對照需 Ref2VA checkpoint／工作流；motion_only 不是光流或姿態控制。
有音訊輸入＝聲線克隆？作者目前記錄聲線轉移失敗；不能由音樂參考案例推成聲音複製成功。
能和語義橋一起掛嗎？不能先假定可行。語義橋 v1 不支援 Ref2VA，兩者先分開驗模式與效果。

以 RefMod 的一個 16×16 latent frame 為例，H3 patchify 後是 64 個參考 tokens；同為一張參考，64×64 latent frame 則是 1,024 個。這反映資訊量與算力取捨，並不是「64 tokens 就能無損保存身份」的品質保證。

影片時序取樣、壓縮與上限可能丟掉來源內容。Text Encode 為 Qwen 重建參考呈現時還會增加 VAE／vision encoder 工作，不能宣稱所有接法都免去前處理。

07

一採與二採：品質、時間與顯存

核心目的：用較低的總計算成本，取得高解析度畫面的細節。

一採先在較便宜的低解析度建立構圖、人物位置、動作與運鏡；二採放大 latent 後，以較少的高解析度步數精修，盡量沿用原內容。它追求的是接近高解析度直接生成的品質，同時比全程高解析度採樣省時。這是設計目的，不是這次實驗已達成的效果；多跑一輪本身不保證品質更好。

一採／二採描述兩個採樣階段。這次 015 的做法是：先用 512×512、20 steps 建立內容，再將影片 latent 以 learned upscaler 放大 1.5 倍，於 768×768、8 steps、denoise 0.3 進行精修。二採是在放大後重新採樣，不是單純 resize，也不是每張影格分開重畫。

和哪個基準比較？品質目的時間取捨
512 一採直接交付嘗試增加可見細節與較高解析度的合理性；不保證更好，也可能改變角色與動作。增加放大與高解析度精修的工作，通常更慢；不能稱為相對 512 的加速。
直接在 768 完整跑 20 steps將較多構圖／運動建立工作放在低解析度，最後用較少高解析度步數修飾。可能較省時，但取決於每步成本、offload、載入與放大開銷；我們尚未做完成的 768 對照，沒有實測加速結論。
512 成片只做一般縮放二採有機會重建新細節；普通縮放主要增加像素，不會經 H3 重新採樣。二採成本較高，且可能產生新的時序或內容問題。

為什麼仍然會 OOM？

768×768 的像素數是 512×512 的 2.25 倍；相同影格數下，影片 latent／patch tokens 也會相應增加。這不等於顯存或耗時精確增加 2.25 倍，但高解析度的 activation、attention 與暫存配置仍需要空間。模型權重也沒有因為只跑 8 steps 就縮小；減少 steps 主要減少重複計算，不保證降低單步峰值。

015 的已觀察結果：一採成功，二採未完成。

512 一採輸出成功，原生執行 1125.83 秒（約 18 分 46 秒）。二採工作重新計算低解析度分支至 20/20，進入 768 精修 0/8 時觸發 HAMI OOM：配置需求 38,903,174,740 bytes（約 36.23 GiB），超過 36 GiB 上限。沒有 768 成片，不能比較品質或宣稱節省時間；此失敗不是 10800 秒執行上限造成。

這次二採工作沒有重用先前一採交付時保存的 latent，因此重新支付了低解析度採樣成本。讀入已壓縮的 MP4 再 VAE encode，也不等同重用原始生成 latent。

目前沒有證據顯示兩採優於直接 768

使用者目前未感受到值得增加流程複雜度的改善，傾向直接使用 768。這個實用上的判斷應保留：目前兩採已增加一輪放大與精修，卻尚未產出可交付的完整結果，因此沒有已證明的品質或速度收益。

但 015 沒有完成 768 二採成片，現有資料不能下結論說它的成片品質比直接 768 差。直接 768 是更單純、適合作為下一個比較基準的流程；應固定 prompt、首幀、seed、LoRA、片長與其餘設定，先確認它能完整生成，再比較品質、耗時與顯存峰值。

直接 768 省去 latent 放大與階段交接，但仍要承擔高解析度單步的記憶體需求；它是否比兩採的峰值低、能否避免 OOM，尚未在這組完整配置下證實。不應先把直接 768 視為已驗證的 OOM 解法。

目前適不適合當預設？

目前不適合。在我們這個 36 GiB 配額、片長與 LoRA 配置下，這份 768 精修配方尚未通過完整生成。穩定交付先以已成功的 512 一採為基準；後續若再研究二採，先處理高解析度階段的記憶體峰值與模型／latent 駐留方式，再用相同片長做完整資格驗證。短煙霧測試成功不能代替完整片長通過，也不能因只差約 0.23 GiB 就認定稍加配額能保證所有後續步驟成功。

以上是本地 015 執行日誌、交付與失敗收據的觀察，不是上游保證；未新增生成工作，也未改底模或配額。

怎麼比較才有答案

  1. 1.

    以 013 作基線

    固定 prompt、首幀、seed、LoRA 順序與強度、20 steps、尺寸、Sage 與 VAE。

  2. 2.

    只切換語義橋

    先比 alpha 0 與 0.10；需要時才另測 0.15，不同時改採樣或兩採設定。

  3. 3.

    分項看結果

    使用者正常播放評估指令、場景保持、打鬥與畫風；另記耗時與技術檢查。

RefMod 則在模式相容後，分開比較原生參考、Full Reference 與 Compressed Reference。使用相同素材、prompt 和 seed，檢查實際保留的素材與 token 數，再評估角色與動作，而不是只看輸出檔案大小。

這是建議測試方式，尚未提交這兩個工具的生成 A/B。語義橋不預設能解決 Wushu v8 黑幕，也不是另一個 Combat 動作 LoRA。
