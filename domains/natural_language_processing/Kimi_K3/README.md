## Introduction

The problem Kimi K3 aims to solve is quite concrete: the open-source community has been catching up fast along the "test-time / RL compute" axis, but along the "pretraining base scale" axis it has long been stuck around 1T-class (roughly one trillion parameters). The report therefore argues that when everyone stacks RL on top of similarly-scaled bases, open-source models converge toward one another while the gap to the strongest closed-source systems actually widens. Kimi K3's answer is to "push both axes to the frontier at once": scale the base up to 3T-class while simultaneously scaling RL, reasoning effort, and long-horizon interaction up to a 1M-token context.

The high-level solution it offers is a native multimodal Mixture-of-Experts (MoE) model: 2.8 trillion total parameters, 104B activated parameters, native vision, and a context window up to one million tokens. The architecture expands the information flow along three dimensions — sequence length via a mix of Kimi Delta Attention (KDA) and periodic Gated MLA, network depth via Attention Residuals (AttnRes), and model width via Stable LatentMoE (896 routed experts, 16 activated per token). Post-training is then SFT → RL across three domains each with three reasoning-effort levels → merging the nine experts back into a single model with Multi-Teacher On-Policy Distillation (MOPD).

How does the report measure whether this approach works? Evaluation spans four capability axes: Reasoning & Knowledge, Coding, Agentic, Vision, against closed-source Claude Fable 5, GPT-5.6 Sol, Claude Opus 4.8, GPT-5.5, and open-source GLM-5.2. The headline conclusion is that Kimi K3 overall still trails the strongest Claude Fable 5 and GPT-5.6 Sol, but consistently beats every other tested model. Below we first reconstruct the mechanism, then scrutinize item by item whether these comparisons are symmetric.

## First Principles

### Architecture overview: expanding information flow along three dimensions

Kimi K3's core design language is "expand the information flow separately along the token, depth, and width dimensions," rather than a single new algorithm. The sequence dimension uses Hybrid Attention (three KDA layers followed by one Gated MLA per block, a 3:1 ratio) to handle long-range token mixing; the depth dimension uses AttnRes to let each layer selectively read the representations of the embedding, the current block, and previous blocks, breaking the bottleneck of traditional residuals that compress all prior information into a single state; the width dimension appends a Stable LatentMoE after each attention layer for sparse channel mixing. Vision is encoded by MoonViT-V2 and projected into the shared embedding space via a lightweight projector. The figure below is the overall architecture from the report's Figure 2.

![Kimi K3 architecture (report Figure 2): on the right, each block of the backbone is "3× (KDA + Stable LatentMoE)" followed by "1× (Gated MLA + Stable LatentMoE)"; every module computes attention weights α over the embedding and previous-block outputs using a learned pseudo-query w (AttnRes, dark diagonal lines). Top-left is the Stable LatentMoE with shared/routed experts, bottom-left is the KDA module (q/k through L2 Norm, q/k/v through ShortConv and Swish, α/β through sigmoid gates), and bottom-right is the MoonViT-V2 native vision path.](imgs/architecture.png)

### KDA: delta-rule linear attention with a channel-wise forget gate

KDA adds a channel-wise forget gate on top of delta-rule recurrence. For a hidden-state sequence $x_t \in \mathbb{R}^d$, a single attention head maintains a fixed-size recurrent state $S_t \in \mathbb{R}^{d_k \times d_v}$, first applying channel decay and then a delta-rule update:

$$S_t = \left(I - \beta_t k_t k_t^\top\right)\mathrm{Diag}(\alpha_t)\, S_{t-1} + \beta_t k_t v_t^\top, \qquad \tilde{o}_t = S_t^\top q_t$$

where $\alpha_t \in (0,1)^{d_k}$ is the per-channel single-step retention factor and $\beta_t \in (0,1)$ controls the delta-rule write strength. Relative to softmax attention, whose KV cache grows with sequence length, KDA trades a fixed-size state for "cheap transitions and reuse" — precisely the physical premise on which the later 1M-context system design rests. The periodically inserted Gated MLA layers then provide unrestricted global token interaction, and all MLA layers use No Position Encoding (NoPE): positional information is carried entirely implicitly by KDA's recurrent decay, so extending the context requires no tuning of RoPE frequency bases or YaRN interpolation.

### Lower-bounded decay: a numerical trick that sends diagonal tiles back to the Tensor Core

KDA's chunkwise parallel form needs to rescale the key by $1/\Gamma_{[t]}^{1\to C}$ (the reciprocal of the cumulative decay), and since $\Gamma$ is a product of $(0,1)$ factors, its reciprocal grows unboundedly and overflows in finite precision. Kimi K3 changes the log-decay mapping from Kimi Linear's unbounded negative-Softplus to a lower-bounded scaled sigmoid:

$$g_t = g_{\min}\,\mathrm{Sigmoid}(e^{A} z_t) \in (g_{\min}, 0), \qquad \alpha_t = \exp(g_t)$$

Fixing $g_{\min} = -5$, each retention factor then satisfies $\alpha_t > e^{-5} \approx 6.7\times 10^{-3}$, the cumulative log-decay over a 16-token tile lies in $(-80, 0)$, and the reciprocal scaling factor is below $e^{80}\approx 5.5\times 10^{34}$, still within BF16 dynamic range. This seemingly-just-an-activation-swap change has a clear system consequence: diagonal tiles no longer need explicit position-pair-wise computation and can go through Tensor Core dense matrix multiplication together with off-diagonal tiles, eliminating the main intra-chunk bottleneck. The figure below draws this "change the mapping → change the computation" causal relationship together.

![Report Figure 3: (a) log-decay parameterization comparison — Kimi Linear uses an unbounded negative-Softplus mapping, while Kimi K3 uses a scaled sigmoid to bound the log-decay from below (shown with $A=0$, $g_{\min}=-5$); (b) diagonal-tile computation comparison — on the left, Kimi Linear's causal diagonal tiles (orange) must be computed explicitly position-pair-by-pair, while on the right, because Kimi K3's decay is lower-bounded, all causal tiles (blue) can go directly through Tensor Core dense matrix multiplication. This figure shows that "lower-bounded decay" is not just a numerical-stability trick but the hardware reason for eliminating the intra-chunk diagonal bottleneck entirely.](imgs/kda_lower_bounded_decay.png)

### Attention Residuals: turning "depth" into a kind of attention too

Standard residuals compress the information of all previous layers into a single state $h_l$, like the temporal bottleneck of an RNN. AttnRes moves what a Transformer does over the sequence into depth: each layer uses a learnable pseudo-query $q_l = w_l$ and performs softmax-kernel attention over the outputs (key/value) of all previous layers, selectively retrieving representations:

$$\alpha_{i\to l} = \frac{\phi(q_l, k_i)}{\sum_{j=0}^{l-1}\phi(q_l, k_j)}, \qquad h_l = \sum_{i=0}^{l-1}\alpha_{i\to l}\cdot v_i$$

where $\phi(q,k)=\exp\!\big(q^\top\mathrm{RMSNorm}(k)\big)$, and RMSNorm prevents layers with large-magnitude outputs from dominating the weights. The full form's memory cost is $O(Ld)$; to reduce cost, the report splits the $L$ layers into $N$ blocks, summing within a block and doing full attention only across blocks, lowering the cost to $O(Nd)$. Kimi K3 takes $N\approx 8$, 12 layers per block, plus the embedding layer for a total of 9 block representations.

### Stable LatentMoE: holding MoE together at sparsity 56

An ordinary MoE gives each selected expert the full $d$-dimensional representation, so communication and weight traffic grow with routing multiplicity. LatentMoE separates "model width" from "routed-expert width": shared experts take the full-width path, while routed experts operate in a compressed latent space (width $\ell$). Kimi K3 can therefore scale channel mixing to 896 routed experts, activating 16 per token, corresponding to a sparsity of $896/16 = 56$. The routed path computes as follows ($N_s=2$ fixed full-width shared experts):

$$u = \sum_{i\in T_k(x)} p_i\, E_i^{\mathrm{routed}}(W_\downarrow x), \qquad y = \sum_{j=1}^{N_s} E_j^{\mathrm{shared}}(x) + W_\uparrow\,\mathrm{RMSNorm}(u)$$

This combination of "four nearly-consecutive matrix multiplications + 2.8-trillion-parameter scale" amplifies two failure modes: activation explosion inside the routed branch, and load-balancing loss of control across nearly $10^3$ experts. Stable LatentMoE holds things steady with three tricks: inserting RMSNorm after aggregation and before up-projection (Normalized LatentMoE); replacing SwiGLU with SiTU-GLU to suppress activations; and Quantile Balancing (QB) for auxiliary-loss-free load balancing. SiTU-GLU applies a smooth upper bound $\beta\tanh(x/\beta)$ separately to the linear factor of the Swish gate and to the up branch, taking $\beta_1=4$, $\beta_2=25$, so the output is bounded $|f(x)|\le \beta_1\beta_2 = 100$ while still approximating SwiGLU near the origin. QB sets each expert's bias to "the router-score quantile matching its target load," estimating the global batch's quantiles in a single forward pass with a histogram, flattening the load across nearly a thousand experts.

### MoonViT-V2: a native vision tower trained from scratch

A key difference from Kimi K2.5 is that Kimi K3's vision encoder MoonViT-V2 is trained entirely from scratch with next-token prediction, rather than following the prior convention of initializing from a contrastively-pretrained model like SigLIP. The report's main stated reason is training stability — the SigLIP-initialized MoonViT-3D has persistently high gradient norms with frequent spikes during joint optimization, whereas the from-scratch MoonViT-V2 stays smooth throughout and does no worse than the SigLIP baseline on vision evaluations. MoonViT-V2 is a 27-layer ViT with about 0.4B (401M) parameters, using RMSNorm and removing the bias of all linear and attention projections; before projection it applies a $2\times 2$ pixel-shuffle downsampling to reduce the number of vision tokens to one quarter, keeping inputs up to $3584\times 3584$ pixels affordable within a 1M context. This "training stability" rationale is directly visible in the report's ablation curves:

![Report Figure 6: vision-tower gradient norm in a pretraining ablation. The SigLIP-initialized MoonViT-3D (blue line) has persistently high gradient norms and frequent spikes (peaks above 0.6) during joint optimization, while the from-scratch MoonViT-V2 (red line) maintains overall lower gradient norms with fewer spikes; the right side is a zoom-in of steps 14k–16k. The report uses this to argue that from-scratch training yields more stable optimization while doing no worse than the SigLIP baseline on vision evaluations.](imgs/moonvit_gradnorm.png)

### A concrete forward walkthrough: shapes, experts, and vision tokens

Walking through with the report's real numbers: a $3584\times 3584$ image, patch size 14, is first cut into $256\times 256 = 65{,}536$ patches, and after $2\times 2$ pixel-shuffle reduced to $16{,}384$ vision tokens, which are interleaved with text tokens into the same context (comfortably within the 1M limit). Entering the backbone, each token in a Stable LatentMoE layer is first projected by $W_\downarrow$ from hidden 7168 down to latent 3584 (the 0.5× in Table 1), the router selects 16 out of 896 routed experts (each expert's MoE hidden is 3072), the weighted aggregate passes through RMSNorm, then $W_\uparrow$ projects it back to 7168 and adds the outputs of the 2 full-width shared experts. The entire backbone is 93 layers, split 3:1 into 69 KDA layers + 24 Gated MLA layers, with one extra Gated MLA layer at the very end to ensure the last layer always does global attention. This is how "2.8T total parameters, only 104B activated per token" holds up: sparsity 56 means the vast majority of the MoE's weights are idle for any single token.

### The meaning of the scale numbers and the 2.5× scaling efficiency

|-|-|-|-|
| #Layers | 61 | 93 | ↑ 52% |
| Total Parameters | 1.04T | 2.78T | ↑ 167% |
| Activated Parameters | 32.6B | 104.2B | ↑ 220% |
| Routed Experts | 384 | 896 | ↑ 133% |

| Attention Mechanism | MLA | Hybrid KDA–MLA | – |

The point is to read each number correctly before discussing comparisons: total 2.78T is the sum of all MoE weights, activated 104.2B is the parameters a single token actually traverses (about a 3.75% activation rate), and the gap between the two is the direct consequence of sparsity 56; 1M is the "training" context length (K2 was 128K), extrapolated via NoPE + KDA recurrence without positional-encoding changes. As for the precise semantics of "2.5× scaling efficiency," the report defines it with a scaling-law curve fitted on held-out OOD validation data: at the same validation loss, the training FLOPs K3 needs are about 1/2.5 of K2's (the horizontal arrow in the figure below). It must be emphasized — this is a vendor-internal fitted curve measuring "the compute efficiency of reaching the same pretraining validation loss," not any downstream benchmark, and the fitting details and data are not disclosed, making it a claim that is hard to independently reproduce.

### Training and post-training recipe: the reproducible and the non-reproducible parts

Pretraining is native multimodal: language and vision tokens are interleaved and jointly optimized under a single next-token-prediction objective from the very first step, using the Per-Head Muon optimizer (splitting the Q/K/V projections along the head dimension and doing Newton–Schulz orthogonalization on each, so that per-head update scales are balanced), a cosine learning-rate schedule with 1% linear warmup, and weight decay 0.1. The context starts training at 8k, is later extended to 64k, and in the cooldown phase ramps from 256K up to 1M, concentrating the expensive long-sequence computation into a small fraction of the total budget. Post-training runs three stages: SFT builds the cold-start policy (and from SFT onward performs quantization-aware training (QAT) with MXFP4 weights / MXFP8 activations); RL runs across three domains — general / general agents / coding agents — each with low/high/max reasoning effort, crossing out to nine experts; finally MOPD distills the nine experts back into a single student, whose per-token reward is the clipped value of the teacher-vs-student log-probability difference:

$$r^d_{\mathrm{opd}}(y_t\mid e,x,y_{<t}) = \mathrm{clip}\!\left(\mathrm{sg}\,\log\frac{\pi^{(d,e)}_{\mathrm{teacher}}(y_t\mid x,y_{<t})}{\pi_\theta(y_t\mid x,y_{<t})},\ -R_{\max},\ R_{\max}\right)$$

Reasoning effort is controlled with a per-problem token budget: each problem gets an initial budget $b_0(x)$ estimated by the cold-start model, trajectories exceeding $\tau\cdot b_0(x)$ have their reward overwritten to $-1$, and annealing $\tau$ from large to small yields the max/high/low levels. What is reproducible and what is not? The algorithmic level (KDA, AttnRes, SiTU-GLU, QB, the MOPD reward form, budget control) is written clearly enough with equations to follow; but the data level is almost non-reproducible — the corpus's domain mixing ratios, rephrasing, knowledge-graph-guided task synthesis, and the actual training data of the nine experts are given only qualitative descriptions, are not released, and combined with the unreleased training code, no outside party can rerun the same model. As for whether this RL scaling truly pushes capability up, the report offers a set of curves across eight tasks as supporting evidence:

![Report Figure 8: scores (solid lines) and average assistant steps (dashed lines) of eight public and internal evaluations during RL as a function of RL FLOPs, covering Coding Experience, General Tool Use, Web Development, Agentic Search, Professional Workflows, Office Deliverables, Agentic Chart Understanding, and Agentic Visual Puzzles. The report's reading is: as RL FLOPs scale up, tool-call step counts increase consistently, accompanied by an across-the-board improvement in overall capability — i.e. the model learns to invest more interaction steps in exchange for higher scores.](imgs/rl_flops_scaling.png)

### System infrastructure: making 1M context and 3T parameters run on limited machines

The report devotes an entire chapter to infrastructure, because three rare challenges — KDA, a 3T-class sparse MoE, and 1M-token agentic RL — occur simultaneously in a single model. A few representative designs: KDA's algorithm-system co-design includes FlashKDA (a CUTLASS chunkwise kernel overlapping intra-chunk computation with cross-chunk state passing) and KDA Context Parallelism (KCP, which decomposes each segment's effect into "a cumulative transition acting on the incoming state" and "a local state generated from zero," two locally-computable quantities, synchronizing the recurrent state with a fixed-size all-gather); pretraining's MoonEP achieves perfect load balancing with "dynamic redundant experts" and proves that at most $E/R$ redundant experts per rank guarantee a feasible solution, making the compute shape statically known and communication zero-copy; 1M agentic RL relies on an external KV cache pool (writing idle prefixes back to CPU DRAM), auto-throttling scheduling, and resumable microVM sandboxes to maintain long-trajectory state. The numbers for the sandbox system AgentENV are very concrete: incremental checkpoint / resume latency as low as 133 ms / 49 ms, paused sandboxes consuming no resources (waiting-for-model-inference can occupy 98% of the sandbox lifetime), a memory overcommit ratio of up to 6.5×, and the entire K3 training and evaluation created 51,219,741 sandboxes spanning 1,505,678 images. What this long-horizon rollout infrastructure has to support is exactly black-box tasks like the one in the figure below, which take dozens to hundreds of steps of tool interaction to complete.

![Report Figure 10: completion curve of the Camera Repair Management System replication task — the agent must reconstruct a hidden 3D camera repair system into a web application through oracle queries; the y-axis is completion as assessed by a verifier, the x-axis is normalized executor tool-call progress. The curve shows Kimi K3 finally reaching 1.000 (full replication), above Opus 4.8's 0.918, GPT-5.5's 0.893, and the previous-generation Kimi K2.6's 0.560. ### Online inference and the KDA-aware prefix cache

The difficulty of online serving is that hybrid KDA–MLA maintains two caches of completely different nature (KDA is a single fixed-size recurrent state per request, MLA is a per-token KV that grows with length), and a prefix is reusable only when both can be restored at the same boundary. Kimi K3 packs the KDA state into the same paged block pool as the MLA KV, and decouples hash granularity (fine, 512 tokens) from physical blocks (coarse, 1024–6144 tokens): the prefix hash runs on MLA's fine hash blocks, while KDA only checkpoints at sparse hash endpoints (usually aligned to conversation-turn boundaries). For example: a 6144-token physical block contains 12 512-token hash blocks, and if a request hits the cache on its first 2800 tokens, it stops at $B = 2560 = 5\times 512$ — deep inside the physical block — and resumes prefill directly from token 2560, recomputing nothing of $[0, 2560)$. The fleet layer then uses cache-aware affinity (routing a session to the cluster holding its prefix cache, and assigning a backup cluster via consistent hashing) and budget-based admission control (giving different request classes their own resource budgets to prevent long-context bursts from dragging down short requests' TTFT).

### Evaluation design and main results

All Kimi K3 evaluations use reasoning effort max, temperature 1.0; the opponents are configured as Claude Fable 5 (with fallback), GPT-5.6 Sol (with potential cyberguards), Claude Opus 4.8, GPT-5.5 (xhigh), GLM-5.2 (max). The report's Table 2 headline conclusion is that Kimi K3 overall stays right behind Fable 5 and GPT-5.6 Sol and consistently beats Opus 4.8, GPT-5.5, and GLM-5.2. By item: GPQA Diamond 93.5% (on par with the frontier), but HLE-Full (43.5% / 56.0%, without/with tools) and CritPt 23.4% clearly trail, showing that research-grade reasoning remains a weak spot; on Coding, ProgramBench reaches a best 77.8%, SWE-Marathon (GPU-kernel-leaning) 42.0% leads Fable 5 by seven points, Terminal-Bench 2.1 88.3% nearly ties GPT-5.6 Sol's 88.8%, and FrontierSWE 81.2% ranks second (behind Fable 5's 86.6%); on Agentic, BrowseComp 91.2%, MCPMark-Verified 94.5%, and several others are best, but on the Elo-based knowledge-work suites (GDPval-AA v2 third, AA-Briefcase second) Fable 5 leads. On third-party evaluation, Artificial Analysis's Intelligence Index v4.1 gives 57.1 (4th of 580 models), behind Fable 5 (59.9) and GPT-5.6 Sol (58.9); WebDev Arena, meanwhile, ranks it first with 1,678 Elo — the first open-source model to top that leaderboard.

## 🧪 Critical Assessment

### Is the problem real and important

The problem "open-source stuck at 1T-class, gap to closed-source widening" is real and observable, and pushing pretraining scale and test-time along both axes together is a reasonable research direction; as the "first open-source 3T-class model," even by vendor self-account, its engineering completeness and the weight release itself have community value. But note that the report implicitly equates "scale" with "capability" — 2.5× scaling efficiency measures the compute efficiency of pretraining validation loss and does not directly equal downstream capability gains, while the downstream headline conclusions in turn rest on a whole set of self-selected evaluation conditions (see below), so "the problem is important" does not mean "these numbers prove the problem is solved."

### The symmetry of baselines and evaluation conditions

This is where the most discount is needed, because multiple comparison conditions are not symmetric. First, the opponents are "loaded": all of Fable 5's results are "with fallback," all of GPT-5.6 Sol's results are "with potential cyberguards," and the report does not quantify the net effect of these mechanisms on scores, so the reader cannot judge how much of the gap comes from the model itself. Second, the harness is not unified: for coding, each model runs one of Kimi Code / Claude Code / Codex, and the internal Table 3 evaluation has Kimi K3 using Kimi Code while others use Claude Code/Codex — when Kimi K3 performs best on its own harness, it is hard to tell whether the contribution is the model or harness compatibility. Third, hardware and versions are recalibrated: SWE-Marathon uses an "H20-calibrated" non-official branch, PostTrainBench runs on H20 (not the official H100), and FrontierSWE scores are recomputed with a specific-date script, all of which make the numbers hard to align with the official leaderboards. Fourth, the same benchmark carries dual numbers (e.g. BrowseComp listed at 91.2%, but 90.4% under full 1M context with no context management), and choosing the presentation most favorable to oneself is a common tactic.

### Novelty vs engineering repackaging

Most components are "refinements standing on one's own and others' shoulders" rather than entirely new inventions: KDA comes from Kimi Linear, AttnRes is an existing method, MLA comes from DeepSeek-V2, and LatentMoE and auxiliary-loss-free routing also have prior work. What genuinely belongs to this report is more like a set of stabilizing and systematizing engineering improvements — lower-bounded scaled-sigmoid decay (sending diagonal tiles back to the Tensor Core), SiTU-GLU's bounded activation, Quantile Balancing's quantile load balancing, MoonEP's $E/R$ redundant-expert upper-bound proof, and the KDA-aware dual-granularity prefix cache. Each of these improvements is reasonable and well-motivated on its own, but when packaged into a single big number like "about 2.5× scaling efficiency," the individual contribution of each component is not decomposed (the report gives only one merged curve and one architecture-comparison table), so it is impossible to tell which changes are truly critical and which are merely incidental byproducts of scaling up.

### Self-defined benchmarks, cyber claims, and reproducibility

The report leans heavily on self-defined/internal evaluations: Table 3's KCB 2.0, ClawBench, MIRA, KAET, Kimi Webdev Bench, etc. are all in-house, and are "frequently refreshed and expanded to track model failure modes" — this amounts to admitting that evaluation is coupled to training iteration, cannot be reproduced externally, and thereby weakens the persuasiveness of the best internal scores. The presentation of cyber capability needs similar caution: Tier 1 claims about 70% confirmed genuine on manual review, including 16 previously unknown vulnerabilities, and Tier 2 solves 14 of 36 tasks (38.9%) beating GLM-5.2's 8, but these are self-built task sets and deliberately exclude the Anthropic/OpenAI frontier models that would refuse cyber tasks, making the "beats the opponents" comparison very thin; by contrast, the report's own cited UK AISI and NIST CAISI independent assessments give more sober numbers — achieving arbitrary code execution on 0 of 41 tasks, which forms a useful counterpoint to the vendor's optimistic narrative and is one of the few external checks in the whole report. On reproducibility, this is "open-weight" but not "open-reproduction": the LICENSE nominally includes inference/training code in Software, but the repo actually contains no training or inference code, and the data recipe, scaling-law fitting, and training data of the nine experts are all unreleased; moreover the Kimi K3 License has two independent commercial restrictions: a Model-as-a-Service provider whose cumulative revenue over any consecutive 12 months exceeds 20 million USD must first make a separate agreement with Moonshot AI; and any commercial product or service with over one hundred million monthly active users or over 20 million USD monthly revenue must prominently display "Kimi K3" in its user interface. So strictly speaking this is "conditional open-weight" rather than fully unrestricted.

### Whether it truly solves the problem, and real-world relevance

Under the pragmatic definition of "open-source-available frontier capability," the report's evidence is fairly strong: best or second-best on several public coding/agentic leaderboards, the first open-source model to top WebDev Arena, and cost efficiency (e.g. BrowseComp at $2.03/task, about half of GPT-5.6 Sol) all point to practical usability. But the full-version claim of "reaching the frontier" does not hold — the report itself admits it still trails Fable 5 and GPT-5.6 Sol overall, and research-grade reasoning (CritPt, HLE) and hardened-target cyber exploit are clear gaps. The reasonable reading is: Kimi K3 pushes the open-source frontier up substantially and ties closed-source on several practical dimensions, but "on par with the strongest closed-source" is not yet supported by this report's evidence, and the supporting numbers in turn depend heavily on the aforementioned asymmetric evaluation conditions, requiring independent, condition-aligned replication to settle. ## One-minute wrap-up

- **Scale expansion**: push the model base to nearly three trillion parameters and a million-token length with extremely high sparsity. Example: 2.8 trillion total parameters, but a single-token forward pass activates only 104B (about 3.75%), with native vision support and up to 1M context.
- **Architectural mechanism**: expand the information flow separately along sequence length, depth, and width. Example: the backbone's 93 layers mix 69 KDA and 24 Gated MLA layers at a 3:1 ratio to handle long sequences, while the MoE picks 16 of 896 routed experts to activate per token.
- **Performance highlight**: matches or surpasses the strongest closed-source models on some public leaderboards. Example: WebDev Arena ranks it first with 1,678 Elo, the first open-source model to top that leaderboard.
- **Evaluation needs discounting**: the winning conclusions depend heavily on "loaded" opponent settings and diverge from external independent assessments. Example: the opponents' results are respectively "with fallback" or "with potential cyberguards," while UK AISI's independent assessment shows K3 achieving arbitrary code execution on 0 of 41 tasks — the optimistic narrative needs condition-aligned replication to settle.
